# Etapes du projet informatique

## 1. Analyse du besoin (Analyse fonctionnelle)

But : comprendre le problème, pas encore la solution.

### Questions clés

- Qui sont les utilisateurs ?
- Quel problème cherchent-ils à résoudre ?
- Que fait-on à la fin du projet ?
- Qu’est-ce qui est hors périmètre ?

### Livrables

- Description du contexte
- Objectifs du projet
- Périmètre fonctionnel
- Contraintes (techniques, temps, données)

Dans le cas de ce projet :

> “Permettre aux futurs consommateurs de consulter la description et la documentation des API existantes et de faire le choix de celles qui seront utiles pour leur projet.”

## Spécifications (Qu’est-ce qu’on va faire exactement ?)

But : définir ce que fait l’application, pas comment elle est codée.

### Contenu

- Cas d’utilisation (use cases)
- Fonctionnalités principales
- Données manipulées
- Règles métier

### Livrables

- Cahier des charges simplifié
- Schémas fonctionnels
- Maquettes simples (wireframes)

> L'Université adore cette étape

## Conception (Comment on va le faire)

But : transformer le besoin en solution technique.

### Contenu

- Architecture (front / back / API)
- Choix technologiques
- Flux de données
- Découpage en composants

### Contraintes

- Technologies supportées
- Intégration dans l'infrastructure SGSI
- Exigences de sécurité

### Livrables

- Schéma d’architecture
- Diagramme de flux (?)
- Structure du projet

> Ici apparaîssent les langauges de programmation, frameworks, API, ESB...

## Développement

But : écrire le code.

### Contenu

- Mise en place du projet
- Développement incrémental
- Intégration progressive

Bonnes pratiques

- Utilisation de Gitlab (Forge UCLouvain)
- Commits réguliers
- Push par features
- Code lisible
- Pas de “génération magique”

> Pour un stage : c’est la plus longue phase.

## Tests et validation

But : vérifier que ça fonctionne comme prévu.

### Types de tests

- Tests fonctionnels
- Tests manuels
- Tests de charge simples
- Gestion des erreurs

### Livrables

- Scénarios de test
- Résultats
- Corrections

> Très bon point pour la note finale.

## Déploiement / Livraison

But : rendre l’application utilisable.

### Contenu

- Mise à disposition sur serveur test
- Configuration
- Documentation utilisateur minimale

### Extra

- Automatisation
- CI/CD

> Même un déploiement “test” compte.

## Documentation & retour d’expérience

But : montrer que le projet est maîtrisé.

### Contenu

- Documentation technique
- Documentation utilisateur
- Analyse critique

### Questions typiques du jury

- Quelles difficultés ?
- Qu’améliorer ?
- Que ferais-tu différemment ?
